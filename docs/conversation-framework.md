# 群聊分段、长期记忆与主动发言

## 当前处理链

1. 微信后端把监控到的群消息写入 `messages`。启动补录写同一张表，但不回放自动回复。
2. 本地规则按群把未整理消息分段。相邻消息间隔、单段条数，或两条连续消息确认的话题变化都可形成边界。话题变化使用中文二字片段和英文词的重合度，是低成本提示，不等于语义模型判断。
3. 自动记忆整理只处理已结束、合计达到最小条数的片段。段落结束可由下一段出现或沉寂时间达到阈值确认。每条新消息和五分钟心跳都会检查；聊天仍在进行时不为每条消息调用 AI。启动补录按最多 100 条的批次追赶历史。
4. 手动整理仍从最早待处理片段开始，可以显式整理未结束片段。整理成功后更新 `group_memory` 的消息游标、数量，并写入该群的 `soul.md`。API 失败不推进游标。
5. 艾特或引用回复读触发前最近 N 条消息。模型判断需要更早背景时才读取本群 `soul.md` 并再次问答；搜索群聊命令仍按关键词查询本群数据库。
6. 主动发言从数据库取最多 500 条最近消息来识别本段，实际给 AI 的内容限于本段且最多 100 条。先检查消息条数、参与人数、持续时间、阶段、冷却、两次发言之间的新消息数及单段发言预算；通过后再应用原有速率档位、评估间隔和概率。AI 仍可选择沉默，严重话题的沉默规则仍在 prompt 中。

## 可调参数

在“记忆 → 对话策略”保存到 `data/conversation_policy.json`，下一次消息处理即生效。主动发言总开关和速率阈值仍在“功能开关 → 主动发言”，后者保存后须重启机器人。

| 参数 | 默认 | 作用 |
| --- | ---: | --- |
| 话题间隔 | 900 秒 | 两条消息相隔达到此值时开新段 |
| 单段最多消息 | 100 条 | 防止无界上下文和过长的单次记忆整理 |
| 话题变化前最少消息 | 8 条 | 避免刚开聊就被短句切碎 |
| 话题相似度阈值 | 0.12 | 两条连续新消息相近、且与之前内容低于阈值时切段 |
| 沉寂后整理 | 600 秒 | 最后一段超过此时间无人发言即可成为已结束片段 |
| 自动整理最少消息 | 12 条 | 短片段先积累；手动整理不受此限制 |
| 主动发言最少消息 | 8 条 | 话题成形后才评估 |
| 主动发言最少人数 | 2 人 | 避免对单人连续发言随意插话 |
| 话题最短持续 | 45 秒 | 防止突发刷屏立即触发 |
| 两次发言间新增消息 | 10 条 | 不连续抢话 |
| 主动发言冷却 | 300 秒 | 同一段内两次发言的最短间隔 |
| 单段最多主动发言 | 2 次 | 0 可关闭主动发言候选 |
| 允许阶段 | 升温和持续讨论 | 可选择也允许降温阶段 |

阶段由本段最近 60 秒与此前 60 秒的消息数粗略判定，不代表 AI 对话题质量的判断。原有速率窗口、档位、随机概率和 AI 的最终沉默判断仍会进一步限制发言。

## 数据和边界

- `messages` 保留已采集或补录的消息正文；`group_memory` 保留整理游标和正文兼容副本；每群文件位于数据库旁 `memory/<群 ID 哈希>/soul.md`。空记忆可在“记忆”页显式创建。
- 分段提示不写入独立的永久话题库，每次从 SQLite 消息及记忆游标计算。旧聊天不因策略调整而删除；调整阈值会改变尚未整理片段的边界。
- 主动发言的冷却和单段预算在进程内保存，重启后重建话题范围，但预算计数重新开始。真正发送仍依赖微信窗口，锁屏与发送动作后的送达确认限制不变。
- 自动整理调用 AI 时可能耗时或超时；失败不推进游标，下一次按原段重试。文件可直接编辑，保存不会推进已整理游标。
