## 流程

实时消息入库 → 观察上一轮接话 → 艾特/引用仍走问答通道；其余消息检查当前话题规模、参与人数、消息时效、安静时段、跨话题冷却和每日额度 → 关键词或停顿后重新展开的话题产生候选 → 检查调用间隔 → AI 判断是否有新增价值 → SKIP/空白/超长均不发送 → 非空回复占用额度并交给现有发送器。

群热度只提供气氛信息，不再让刷屏提高插话概率。关键词仅预筛，不代表“命中就回复”。没有定时主动唤醒：没人发消息时不会凭空发送。

## 设置与保存

AI 配置新增“助手性格与品味”和“主动发言指令”，存入 `data/prompts.json`，与问答指令分开。可写具体偏好，例如“喜欢追问做法与细节；对大新闻先核对事实；不喜欢泛泛总结；被证据说服会改口”。不要求模型伪造人类经历。

记忆 → 对话策略中新增或调整以下参数，存入 `data/conversation_policy.json`，下一次候选判断生效。

| 参数 | 默认 | 作用 |
|---|---:|---|
| proactive_cooldown_sec | 3600 秒 | 跨话题冷却；问答回复也重置冷却 |
| proactive_daily_limit | 6 | 每群每天生成主动回复的上限，0 禁用 |
| proactive_eval_sec | 300 秒 | 两次候选 AI 判断的最短间隔；连续 SKIP 会退避，最多 16 倍 |
| proactive_context_count | 40 条 | 主动发言的独立上下文窗口 |
| proactive_max_chars | 80 字 | 超过直接不发，避免截断；指令仍建议约 40 字 |
| proactive_quiet_start / end | 0 / 8 | 本机时区的安静时段；支持跨午夜；相同则关闭 |
| proactive_feedback_sec | 600 秒 | 接话观察时间 |
| proactive_feedback_messages | 5 条 | 接话观察条数；时间或条数先到则结算 |
| proactive_ignored_limit | 3 次 | 连续无明确接话后冷却翻倍；后续明确回应恢复 |
| proactive_allowed_moves | 追问、带细节的回应 | 模型允许采用的动作；可自行增加接梗、补充信息、表态等 |
| proactive_trigger_words | 观点、分享、宠物美食与问句关键词 | 用顿号分隔，预筛候选机会 |
| proactive_resume_gap_sec | 120 秒 | 最新两条消息间隔达到此值可成为候选 |

已有话题人数、年龄、消息量、每段额度、阶段设置继续起作用。已保存的旧参数值不会被新默认覆盖：例如原来保存了 300 秒冷却，请在界面改成 3600–5400 秒。

## 记忆与反馈边界

- 主动发言仅取固定四块结构中【群里的事】、【我说过的立场】和当前上下文中出现的人对应的个人行；省略【观察中】与标注“不主动提”的行，上限 2000 字。旧的不分块记忆不自动迁移，也不整份注入；可在记忆编辑器整理格式。
- 这一轮没有修改记忆写入/夜间沉淀算法，也不会自动把生成的观点写入【我说过的立场】。分享对话提出的观察升级、版本回滚、候选笔记合并与夜间整理属于另一组记忆改动。
- SQLite 新增 `proactive_state` 保存日期、次数、上次回复时间、无人接话次数和观察进度；重启与切段不会重置冷却/当日额度。反馈不保存聊天正文。
- 生成回复即占额度，包括随后发送失败；不是微信送达证明。反馈中的后续艾特/引用是“有人继续与助手互动”，无法精确归因到某次插话；普通相邻消息不算接话。时间到期在下一条消息到来时结算。
- 指令要求 SKIP，代码去掉标点、空白后解析，大小写不敏感。输出超长不截断、不发送。没有新增联网工具，不声称核实新闻或看见无法读取的图片。
